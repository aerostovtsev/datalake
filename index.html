02Контуры

и при этом

разграничение — по данным,
а не по людям.

Права у всех сотрудников одинаковые. Контур определяет, что за данные, а не кто спрашивает. Роль свободного SQL не видит контактные представления даже в information_schema. Холодная база — для поиска лидов. Клиентский контур — для продаж. Контактный — только поштучно, по одному ИНН за вызов.

03Как работает

Семь шагов
от вопроса до ответа.

Агент не имеет прямого доступа к базе: он вызывает инструменты сервера, те выполняют запросы под read-only ролями. Каждый запрос привязан к сотруднику.

  1. 01Сотрудник задаёт вопрос на русском«топ клиентов за 2025»
  2. 02MCP-клиент — Claude Code, Codex, OpenCode, Cursorлюбой MCP-клиент
  3. 03OAuth 2.1 + PKCE через ZitadelJWT привязан к сотруднику
  4. 04MCP Toolbox выбирает инструментиз tools.yaml — единственного источника правды
  5. 05Роль mcp_agent или mcp_contactsвитрины без ПДн · контакты по одному ИНН
  6. 06PostgreSQL 15, схема mcpтолько представления · только чтение
  7. 07Агент показывает SQL и ответи каждый запрос виден в аудите

Если агент не понял вопрос, запрос будет валидным, а число — неверным. Поэтому инструкция требует показывать SQL и называть трактовку там, где от неё зависит число: «компания» — юрлицо, ИП или оба; «выручка» — наши продажи или выручка контрагента по ФНС.

Контакты — строго поштучно.

Телефон, email, ФИО и адреса — по одному ИНН за вызов, под отдельной ролью. Массовая выгрузка невозможна архитектурно.

top_clients_by_revenue · find_leads

Готовые отчёты.

Топ покупателей, профиль контрагента, продажи по периодам и группам товаров, поиск лидов по холодной базе, финотчётность по ИНН, клиенты без сделок, отчёт о качестве данных.

column "registration_date" does not exist

Отказ вместо выдумки.

Полей, которых нет в базе, в представлениях нет намеренно: похожих колонок не существует, подставить нечего. Запрос по ним даёт ошибку, а не пустую выборку.

05Безопасность

Граница — права роли,
а не парсер приложения.

Read-only выставлен на самой роли Postgres, а не в коде: обойти настройку роли нельзя. Контакты доступны только поштучно: чтобы выгрузить 750 тысяч контактов, нужно 750 тысяч вызовов — и это видно в логах на первой сотне.

Модель внешняя: каждая отданная строка покидает контур компании. Это осознанное решение, отсюда лимиты на выдачу и поштучный доступ к контактам. Сервер не должен быть доступен из интернета: только корпоративная сеть или VPN.

06Выгрузка

Большой список — это файл,
а не контекст модели.

Предел в 1000 строк — не про безопасность, а про физику: строка из десяти колонок стоит 30–60 токенов, тысяча строк съедает почти всё окно модели. Плюс модель внешняя. Поэтому выгрузка идёт мимо модели: SQL не дублируется — скрипт берёт запрос из того же tools.yaml.

  1. 01
    Вопрос на самом деле про агрегат. «Каких клиентов больше всего» — это count, sum, топ-N. Ответ в двадцать строк.
  2. 02
    Надо посмотреть, что там. Сначала count(*) с тем же WHERE, потом решение. Для «посмотреть глазами» хватает двадцати строк.
  3. 03
    Нужен весь список — это выгрузка. CSV и XLSX до миллиона строк, серверный курсор порциями по 5000, таймаут 120 с. Контакты недоступны и здесь.
